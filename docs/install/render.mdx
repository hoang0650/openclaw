Deploy OpenClaw on [Render](https://render.com) using the repo's `render.yaml` Blueprint. It declares the service, disk, and environment variables in one file.

## Prerequisites

- A [Render account](https://render.com) (free tier available)
- An API key from your preferred [model provider](/providers)

## Deploy

[Deploy to Render](https://render.com/deploy?repo=https://github.com/openclaw/openclaw)

This creates a Render service from `render.yaml`, builds the Docker image, and deploys it. Your service URL follows the pattern `https://<service-name>.onrender.com`.

The Blueprint pins the active config to the persistent disk, copies the repo's `openclaw.json` into that path on each deploy, and starts the Gateway with `--bind lan` so Render's ingress can reach the container.

Render is a **proxy TLS termination** deployment: browsers connect to the public `https://` URL, and Control UI upgrades to `wss://` on that same origin, while the Gateway inside the container still listens on plain HTTP for Render's internal proxy hop. Do **not** enable `gateway.tls.enabled` just because the public Render URL is HTTPS.

## The Blueprint

```yaml
services:
  - type: web
    name: openclaw
    runtime: docker
    plan: starter
    healthCheckPath: /healthz
    dockerCommand: >-
      /bin/sh -c 'install -d -m 700 /data/.openclaw /data/.openclaw/workspace &&
      cp /app/openclaw.json /data/.openclaw/openclaw.json &&
      exec node openclaw.mjs gateway --bind lan --port 8080'
    envVars:
      - key: OPENCLAW_GATEWAY_PORT
        value: "8080"
      - key: OPENCLAW_GATEWAY_BIND
        value: lan
      - key: OPENCLAW_STATE_DIR
        value: /data/.openclaw
      - key: OPENCLAW_CONFIG_DIR
        value: /data/.openclaw
      - key: OPENCLAW_CONFIG_PATH
        value: /data/.openclaw/openclaw.json
      - key: OPENCLAW_WORKSPACE_DIR
        value: /data/.openclaw/workspace
      - key: OPENCLAW_GATEWAY_TOKEN
        generateValue: true # auto-generates a secure token
    disk:
      name: openclaw-data
      mountPath: /data
      sizeGB: 1
```

| Feature               | Purpose                                                    |
| --------------------- | ---------------------------------------------------------- |
| `runtime: docker`     | Builds from the repo's Dockerfile                          |
| `healthCheckPath`     | Render monitors `/healthz` and restarts unhealthy instances |
| `dockerCommand`       | Seeds `/data/.openclaw/openclaw.json` from the repo and binds the Gateway for Render ingress |
| `generateValue: true` | Auto-generates a cryptographically secure value            |
| `disk`                | Persistent storage that survives redeploys                 |

## TLS model on Render

- Public browser traffic uses Render-managed TLS, so the dashboard URL is `https://...` and the browser's WebSocket is `wss://...`.
- The container should keep `gateway.mode: "local"` and `bind: "lan"` so Render's internal proxy can reach port `8080`.
- Keep shared-secret auth (`gateway.auth.mode: "token"` or `"password"`) unless you add your own identity-aware proxy. A plain TLS terminator or load balancer is **not** a `trusted-proxy` deployment.
- `gateway.controlUi.allowedOrigins` must include the exact HTTPS browser origin you use, such as `https://openclaw.phhotel.vn`.
- Only enable `gateway.tls.enabled` when OpenClaw itself is the TLS terminator and you supply real cert/key files to the Gateway.

## Choosing a plan

| Plan      | Spin-down         | Disk          | Best for                      |
| --------- | ----------------- | ------------- | ----------------------------- |
| Free      | After 15 min idle | Not available | Testing, demos                |
| Starter   | Never             | 1GB+          | Personal use, small teams     |
| Standard+ | Never             | 1GB+          | Production, multiple channels |

The Blueprint defaults to `starter`. To use the free tier, change `plan: free` in your fork's `render.yaml` — note that with no persistent disk, OpenClaw state resets on each deploy.

## After deployment

### Access the Control UI

The web dashboard is available at your Render HTTPS origin, such as `https://<your-service>.onrender.com/` or your attached custom domain like `https://openclaw.phhotel.vn/`. Connect using the shared secret: the auto-generated `OPENCLAW_GATEWAY_TOKEN` (find it in **Dashboard → your service → Environment**), or your password if you switched to password auth.

### Logs

**Dashboard → your service → Logs** shows build logs (Docker image creation), deploy logs (service startup), and runtime logs (application output).

### Shell access

**Dashboard → your service → Shell** opens a shell session. The persistent disk is mounted at `/data`.

### Environment variables

Edit variables in **Dashboard → your service → Environment**. Changes trigger an automatic redeploy.

The Render Blueprint keeps Git as the source of truth for `openclaw.json`: every deploy copies `/app/openclaw.json` into `/data/.openclaw/openclaw.json` before startup. If you edit config from the Control UI or shell, those changes are overwritten on the next deploy unless you also commit them back to the repo.

For public HTTPS use, keep the config aligned with the actual browser origin. If you switch between a custom domain and the default `onrender.com` hostname, add whichever exact HTTPS origin you plan to use to `gateway.controlUi.allowedOrigins` before redeploying.

### Auto-deploy

Render redeploys automatically when the connected repo's branch gets a new commit. If you deployed straight from `openclaw/openclaw` instead of your own fork, you have no push access to trigger that, so update by running a manual Blueprint sync from the Dashboard, or point the service at your own fork.

## Custom domain

1. **Dashboard → your service → Settings → Custom Domains**
2. Add your domain
3. Configure DNS as instructed (CNAME to `*.onrender.com`)
4. Render provisions a TLS certificate automatically

## Scaling

- **Vertical**: change the plan for more CPU/RAM. Usually sufficient for OpenClaw.
- **Horizontal**: increase instance count (Standard plan and above). Requires sticky sessions or external state management since OpenClaw keeps runtime state on the local disk.

## Backups and migration

From the Render Dashboard shell, export state, config, auth profiles, and workspace at any time:

```bash
openclaw backup create
```

This creates a portable backup archive. See [Backup](/cli/backup).

## Troubleshooting

### Service will not start

Check the deploy logs in the Render Dashboard. Common issues:

- Missing `OPENCLAW_GATEWAY_TOKEN` — verify it is set in **Dashboard → Environment**
- Port mismatch — ensure `OPENCLAW_GATEWAY_PORT=8080` so the gateway binds to the port Render expects
- Config mismatch — run `openclaw config file` in the Render shell and confirm it prints `/data/.openclaw/openclaw.json`
- Container reachable only locally — ensure the service starts with `--bind lan` (the Blueprint's `dockerCommand` already does this)
- `origin not allowed` in the browser console or deploy logs — add the exact HTTPS dashboard origin to `gateway.controlUi.allowedOrigins` and redeploy
- Trusted-proxy auth errors behind Render — revert to shared-secret token/password auth unless you have added your own identity-aware reverse proxy in front of Render

### Slow cold starts (free tier)

Free tier services spin down after 15 minutes of inactivity; the first request after spin-down takes a few seconds while the container starts. Upgrade to Starter for always-on.

### Data loss after redeploy

Happens on the free tier (no persistent disk). Upgrade to a paid plan, or regularly export a backup with `openclaw backup create` from the Render shell.

### Health check failures

If builds succeed but deploys fail, the service may be taking too long to start or `/healthz` may not be reachable. Check:

- Build logs for errors
- Whether the container runs locally with `docker build && docker run`
